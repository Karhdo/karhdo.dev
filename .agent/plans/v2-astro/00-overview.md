# v2-astro — Rebuild karhdo.dev from Next.js 16 to Astro

## Summary

Replace the Next.js 16 + Contentlayer + Prisma blog on branch `v2` with an Astro 7 site (Bun, TypeScript strict, Tailwind CSS v4, MDX content collections, Expressive Code, Biome, Drizzle, React 19 islands only where interactivity is required), deployed to Vercel with `@astrojs/vercel` on the Node runtime. Every v1 route and feature is carried over, URLs of existing posts stay identical, and the existing Postgres `stats` table (views + reactions) is reused through Drizzle with no destructive migration. The UI is refreshed: evolved Tokyonight palette, bento-grid homepage, view transitions, glassy cards, ⌘K command palette (Pagefind), Satori OG images, reading progress bar, sticky TOC, flash-free light/dark mode.

## Architecture Decisions

- **Output mode: static by default, per-route opt-out** — Astro 7 prerenders every route unless it exports `prerender = false`. All content pages (`/`, `/blog/**`, `/tags/**`, `/about`, `404`), feeds, robots, and OG images are prerendered at build; only `src/pages/api/*` and `/projects` are on-demand Vercel Functions (Node runtime). This keeps pages on the CDN, keeps Lighthouse high, and means the DB/Spotify/GitHub are never called at build except for OG/feeds (which call nothing external).
- **`/projects` rendered on demand with CDN caching** — v1 fetched GitHub stars at request/build time. v2 renders on demand and sets `Cache-Control: public, s-maxage=3600, stale-while-revalidate=86400` so the Vercel CDN serves it; stars stay fresh without a rebuild and without shipping the GitHub token to the client. Falls back to static project data if the API fails.
- **Shared files in parallel phases (m2)**: `src/pages/index.astro` (15) and `PostLayout.astro` / `PostHeader.astro` (12) pre-create stub components, and each p5 task fills only its own stub. The env schema pre-registers every key, including `ANTHROPIC_ADMIN_API_KEY`, in task 03. `astro.config.mjs` is still edited by 23, 24 and 25 in p5; those three are **merged one at a time** (rebase on latest `v2`, re-run the build), adding only their own integration or option.
- **Homepage stubs, one owner each** — task 15 creates `SpotifyCard`, `TokenBurnCard`, `GithubActivityCard`, `BlogStatsCard` and `Snowfall` as fixed-size stub components and wires them into `src/pages/index.astro` once. Tasks 19, 31, 20, 30 and 29 each fill only their own stub file and never edit `index.astro`, so the p5 tasks don't conflict (reviewer 29-e).
- **Footer statusline data is build-time** — `scripts/build-info.mjs` runs from `astro.config.mjs` and resolves the GitHub stars (REST, token optional), the commit sha (`VERCEL_GIT_COMMIT_SHA` → `git rev-parse`), the commit date (`git log -1 --format=%cI` → GitHub REST fallback) and the branch (`VERCEL_GIT_COMMIT_REF` → `git branch --show-current`). It is injected with Vite `define` as `__BUILD_INFO__`, so prerendered pages and the `/projects` function share it and no function runs git. Failures degrade the segments and never fail the build. The relative commit time and the HCMC clock (`Intl`, DST/half-hour safe) are computed in the browser. The version switcher lists `SITE.versions` (main → karhdo.dev, v1 → v1.karhdo.dev, not live yet).
- **Token burn limitations** — the Anthropic Admin API reports only **API-key usage in the organization** (Claude Pro/Max subscription usage, including subscription Claude Code, is excluded) and needs an org Admin key. Daily buckets are **UTC**, and the card labels them UTC. Cost excludes Priority Tier, and data lags about 5 min plus the 15-min CDN cache.
- **Homepage live widgets are client-fetched islands** — the bento page is prerendered; Spotify (`client:visible`, polls `/api/spotify` every 30 s only while the tab is visible), GitHub activity and Blog stats (`client:visible`, one fetch each) are small React islands. Location/time and typed bios are vanilla `<script>` (no React). Latest post and tech stack are pure Astro.
- **Island hydration policy** — React only for stateful UI: `Reactions` + `ViewCounter` (`client:visible` / `client:idle`), the ⌘K palette (not an island: a vanilla loader dynamic-imports the React + cmdk chunk and Pagefind on first open, so pages without other islands ship no React), `Comments` (Giscus, `client:visible`), `SpotifyNowPlaying`, `GithubActivity`, `BlogStats`, `NewsletterForm` (`client:visible`). Everything on every page (header, footer statusline, version switcher) is vanilla, as are the Token burn card and snowfall. Theme toggle, mobile nav, statusline clock, version switcher, Token burn, snowfall canvas, TOC scrollspy, reading progress, scroll-to-top, image zoom and typed bios are Astro components with inline/bundled `<script>`s re-initialised on `astro:page-load` (required with `<ClientRouter />`). No SWR: a tiny `fetchJson` helper + React state.
- **Env handling via `astro:env`, v1 names kept** — schema in `astro.config.mjs`: server secrets `POSTGRES_URL`, `GITHUB_API_TOKEN`, `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `SPOTIFY_REFRESH_TOKEN`, `BUTTONDOWN_API_KEY`, and the **one new** secret `ANTHROPIC_ADMIN_API_KEY` (task 31, pre-registered in 03, set in Vercel **Production only**, never exposed to the client); server **public** `NEXT_PUBLIC_GISCUS_REPO`, `NEXT_PUBLIC_GISCUS_REPOSITORY_ID`, `NEXT_PUBLIC_GISCUS_CATEGORY`, `NEXT_PUBLIC_GISCUS_CATEGORY_ID`, `UMAMI_WEBSITE_ID`. All `optional: true` so builds without secrets succeed and code degrades gracefully. The public ones are read in prerendered Astro components (`Analytics.astro`, `PostLayout.astro`) and passed to islands as props, so no `context: 'client'` vars and **no Vercel env renames**.
- **DB connection on serverless** — `src/lib/db/client.ts` creates one module-scoped `postgres()` client lazily (`max: 3`, `idle_timeout: 20`, `connect_timeout: 10`, `prepare: false` because the Neon `-pooler` host runs PgBouncer in transaction mode, `ssl: 'require'`) wrapped with `drizzle-orm/postgres-js`. Warm Vercel (Fluid) instances reuse it. Only API routes import it, so it never runs at build. Writes are single-statement `INSERT … ON CONFLICT (type, slug) DO UPDATE SET col = stats.col + $delta` (atomic, no read-modify-write race as in v1).
- **The one schema addition: `stats_daily`** — the Blog stats card's 30-day chart and delta need daily history, and v1's `stats` only has cumulative counters. v2 adds `stats_daily (type, slug, date, views)` with PK `(type, slug, date)` and a date index. It is created by the reviewed, idempotent, additive-only `db/manual-migrations/0001_create_stats_daily.sql`, run manually with `psql` against the Neon direct host (on a Neon branch first), **never** via drizzle-kit. It doesn't touch `stats`, the `StatsType` enum or any existing row. The view POST upserts into it after the main counter update, best-effort (a missing table is tolerated), so deploy and migration order don't matter. History starts on the migration date; there is no backfill (task 05, 18, 30).
- **Drizzle maps the existing table, never migrates it** — `pgEnum('StatsType', …)`, `pgTable('stats', …)`, `primaryKey({ name: 'stats_pkey', columns: [type, slug] })`. `drizzle.config.ts` sets `tablesFilter: ['stats']`, `strict: true`, a header comment forbidding push/migrate, and is used only for `drizzle-kit pull` (against the Neon **direct** host, `POSTGRES_URL_DIRECT`) into a git-ignored dir to diff against the hand-written schema. No `migrations/` folder, no `push`/`migrate` scripts. `prisma/` is deleted after verification (history keeps it).
- **Content via content layer (glob loader)** — MDX moves from `data/blog` → `src/content/blog`, `data/authors` → `src/content/authors`. Entry `id` = filename without extension = v1 slug, so `/blog/{id}` matches v1 exactly. Drafts excluded in production. Reading time computed from `entry.body` in `src/lib/content.ts`; TOC from `render()` headings (depth 2–3).
- **Markdown processor: explicit unified** — Astro 7 defaults to the Sätteri processor; top-level `markdown.remarkPlugins/rehypePlugins` only work through a deprecated auto-coercion, and `rehypeHeadingIds` would run after user rehype plugins. So `markdown: { processor: unified({ remarkPlugins: [remarkCodeTitles, remarkAlert], rehypePlugins: [rehypeHeadingIds, [rehypeAutolinkHeadings, …]] }) }` with `unified`/`rehypeHeadingIds` from `@astrojs/markdown-remark`; MDX inherits it. The build log must show no markdown deprecation warning.
- **Code blocks: Expressive Code** — `tokyo-night` (dark) + folke's Tokyonight Day theme (`tokyonight_day.tmTheme`, MIT) converted once to JSON and loaded with `ExpressiveCodeTheme.fromJSONString` (light), `themeCssSelector` on `[data-theme]` plus `useDarkModeMediaQuery` for the JS-off fallback, per-theme `styleOverrides` (no dark frames in light mode). Features: filename title tab (`remark-code-titles` turns `ts:path/file.ts` into `title="…"` and passes the rest of the meta through), a small language-badge EC plugin, copy button, `{2-3}`/`ins={4}`/`del={5}` markers, line numbers only with `showLineNumbers`. `expressiveCode()` is listed before `mdx()`.
- **Theme without flash, `data-theme` attribute** — tokens in `theme.css` (the **only** place colours are defined, mirrored for non-CSS uses in `palette.ts`; every colour is Tokyonight, with no brand or off-palette hex values, enforced by a `lint:palette` grep in CI): `:root` = Tokyonight Day, `:root[data-theme="dark"]` = Night, and the same dark block under `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }` so JS-off visitors get their OS scheme. Tailwind `dark:` is a `@custom-variant` covering both. An `is:inline` head script resolves `localStorage.theme` (`light|dark|system`) + `prefers-color-scheme` and sets `data-theme` before paint; re-applied on `astro:after-swap`. `theme-color` = `#e1e2e7` / `#16161e`. Giscus receives its theme via `postMessage`; snowfall observes the attribute.
- **Motion system (CSS-first)** — easing tokens `--ease-out`/`--ease-spring` and all keyframes live in `animations.css` (06). Effects run only under `prefers-reduced-motion: no-preference`; content is complete at rest (nothing starts at opacity 0, `.reveal` uses `animation-timeline: view()` inside `@supports` with no JS fallback). Only transform/opacity/filter/clip-path are animated, so there's no CLS. Infinite loops are paused off-screen (`PauseOffscreen`). One `pointermove` listener drives tilt + spotlight (`PointerFx`). Count-up numbers are server-rendered final values animated once in view. Page (`main` → `page`) and `nav-pill` view transitions run through ClientRouter, and the circular theme reveal is scoped with `html[data-theme-switching]` so it doesn't override page transitions. The brand is an animated `karhdo.dev` wordmark with no dot (09): text only (no avatar or dot), with a terminal-style decode once per session in the header, a letter wave on hover/focus, and a 75 %-width green underline shown only on hover/focus; it's static under reduced motion and correct server-rendered text without JS. Ownership is spread across 06/09/12/13/15/17/18/20/29/30/31, and task 26 orchestrates and audits it.
- **Brand icons via `simple-icons`** — the Daily stack marquee (14 tools from typed `SITE.stack`, 2 opposite rows, duplicated track `aria-hidden`, static scrollable rows under reduced motion) and the project chips render `simple-icons` paths as inline SVG at build time through `SimpleIcon.astro` (08), shipping no JS.
- **Project cards** — a featured EcomHeat card (fact tiles, Visit product) plus browser-framed cards, with screenshots moved to `src/assets/projects/` and served via `astro:assets` + the Vercel image service (AVIF/WebP, responsive widths, lazy). `karhdo-blog.png` stays in `public/` as the OG fallback (17).
- **View transitions** — `<ClientRouter />` in `BaseLayout`, `transition:name` on post titles/cards for list→post morph, `transition:persist` on the header/theme toggle and Spotify island. All motion wrapped in `@media (prefers-reduced-motion: no-preference)`; the router falls back to no animation when reduced motion is requested (`fallback="swap"` behaviour + CSS guard).
- **OG images at build** — `src/pages/og/[...slug].png.ts` prerendered with `getStaticPaths()` over published posts; Satori renders JSX-object trees with Outfit (woff from `@fontsource/outfit`) to SVG, `@resvg/resvg-js` converts to PNG. Runs only during `astro build` (native module never shipped to functions because the route is prerendered). Post `<meta og:image>` points to `/og/{slug}.png` unless frontmatter `images` is set.
- **Pagefind after build** — `astro-pagefind` integration indexes the static output in `astro:build:done` (with the Vercel adapter the client dir is `.vercel/output/static`; task 23 verifies and, if the integration picks the wrong dir, replaces it with a `postbuild` step `bunx pagefind --site .vercel/output/static`). Only `<article data-pagefind-body>` on post pages is indexed. The palette dynamically imports `/pagefind/pagefind.js` (`/* @vite-ignore */`), so nothing is bundled.
- **Security headers in `vercel.json`** — static assets are served by the CDN without passing through middleware, so headers (CSP, Referrer-Policy, X-Frame-Options, X-Content-Type-Options, X-DNS-Prefetch-Control, HSTS, Permissions-Policy) are declared in `vercel.json` `headers` for `/(.*)`, byte-for-byte from v1 `next.config.mjs` (CSP extended only where v2 needs it: `analytics.karhdo.dev`, and `'wasm-unsafe-eval'` for Pagefind's WASM). No middleware.
- **Bun as package manager/runner, Node as runtime** — commit `bun.lock`; Vercel detects it and runs `bun install`; build command `bun run build`. Functions run on Node 24 (`@astrojs/vercel` default; set Node 24.x in Vercel project settings / `engines.node`). Do **not** set `bunVersion` in `vercel.json` (that opts Functions into the Bun runtime, which the user did not choose).
- **Biome, lefthook, tests, CI** — single `biome.json` (matching v1 `.prettierrc`: single quotes, semicolons, lineWidth 120, 2 spaces, trailing commas `es5`; `useSortedClasses` stands in for `prettier-plugin-tailwindcss`), `tailwindDirectives` CSS parsing, Astro overrides. lefthook replaces Husky + lint-staged (`biome check --staged` on pre-commit). `bun test` covers pure modules only (stats schema/handler incl. v1 absolute payloads → 400, origin allowlist, tag counts vs v1 `tag-data.json`, reading time, `remark-code-titles`, `emojiCodepoint`, GitHub streak, summary formatting, theme-token parity), because `bun test` can't resolve `astro:*` virtual modules. `.github/workflows/ci.yml` runs install --frozen-lockfile, `biome ci`, `astro check`, `bun test`, build.
- **Dev-only preview pages** — `src/integrations/dev-pages.ts` injects `/dev/*` routes from `src/dev-pages/` only under `astro dev` (tokens, components, content, MDX fixture), so they never reach the build, sitemap or Pagefind.
- **Trailing slashes and build format** — `trailingSlash: 'never'`. `@astrojs/vercel` forces `build.format: 'directory'`, so pages are emitted as `blog/<slug>/index.html` etc. and served at `/blog/<slug>` (no slash), matching v1's Next.js URLs.
- **Path alias** — `"paths": { "~/*": ["./src/*"] }` in `tsconfig.json` **without `baseUrl`** (deprecated in TypeScript 6, error TS5101, which breaks `astro check`); `extends: "astro/tsconfigs/strict"`.

> **Note from task 06 review (applies to every task porting mockup CSS):** the mockup uses `var(--sans)` / `var(--mono)`; in the codebase these are `var(--font-sans)` / `var(--font-mono)`. Use raw colour tokens (`var(--blue)`) in scoped styles, not `--color-*` (those exist only when a Tailwind utility uses them). Component classes such as `.glass` and `.shimmer` live in `@layer components`, so Tailwind utilities override them; `prose.css` overrides live in `@layer utilities` after the typography plugin (use `not-prose` to escape). The mockup `pulse` keyframe replaces Tailwind `animate-pulse`; use `animate-shimmer` for skeletons.


> **Note from task 09 review (applies to all UI tasks):** in the Tokyonight Day theme, `--faint` (~2.4-2.9:1) and `--muted` (~3.6-4:1) fail WCAG AA for small text. Use `--fg-soft` or `--fg` for any small text that carries meaning, and keep `--faint`/`--muted` for decorative marks and large text only. Never put `--bg` text on a `--blue` background in Day (3.1:1); use `--heat-4` background with `--surface-solid` text for solid accent chips (4.88:1).


> **Note (found during task 13):** for once-only listener guards, never write `el.dataset.bound = ""` and then test `if (el.dataset.bound)`: the empty string is falsy, so it rebinds on every `astro:page-load`. Use `el.dataset.bound = "true"`, or test `!== undefined`.


> **Note (found during task 16):** `astro preview` / `bun run preview` does NOT work with `@astrojs/vercel` ("does not support the preview command"). To check built pages locally, serve `.vercel/output/static` with a small static server that applies the `config.json` routes (incl. the `^/.*$ → /404.html` 404 fallback), or use `bunx vercel dev` / `vercel build` + `vercel deploy --prebuilt=false` on a preview. On-demand routes (`/api/*`, `/projects`) need `bun dev`. Parallel builds share `.vercel/output`, so snapshot it right after building.


> **Note (found during task 12):** never combine `animation:` shorthand with `animation-timeline: view()`. The CSS minifier folds them into `animation: … view()`, which Chrome rejects, silently dropping the rule. Use longhands (`animation-name`, `animation-duration: auto`, `animation-timing-function`, `animation-fill-mode`, `animation-timeline`, `animation-range`), as `.reveal` in `src/styles/animations.css` does.


> **Note (found during task 17):** on `@astrojs/vercel`, `<Image>`/`getImage` default to `quality=100`. Always pass an explicit `quality` (75, or `"high"` = 80) on every image.


> **Implementation note (task 18):** views and reactions ship as plain module scripts, NOT React islands (`ViewCounter.tsx`/`Reactions.tsx` in the spec were replaced with the lead's approval), so post pages hydrate no React for stats. Abuse: the Origin check stops browser CSRF, but scripted clients can forge Origin (+1 view / +5 per reaction per request). Follow-up for task 28: add a Vercel WAF rate-limit rule on `/api/stats` (e.g. ~30 POST/min per IP).


> **Cache-header rule (found in task 31 review, applies to every on-demand route):** never send `s-maxage` / `stale-while-revalidate` in `Cache-Control` without a browser `max-age`: browsers then serve stale responses for the SWR window. Use `Cache-Control: public, max-age=0, must-revalidate` for the browser plus `Vercel-CDN-Cache-Control: max-age=N, stale-while-revalidate=M` for the CDN.
